# Strong's-Tagged Source Text Duplication Scan

Generated by `tool/source_text_verification/verify_strongs_duplicates.py`.
Re-run that script to regenerate this summary and the accompanying
`strongs_duplication_scan_report.csv` / `.json`.

## Revelation 1:1 — confirmed genuine duplication/tagging error

Textus Receptus (Scrivener 1894, per STEPBible's TAGNT — this exact word
list is unanimous across NA27/28, TR, Byz, WH, Treg, SBL, and Tyndale
House editions for this verse, i.e. not a variant-reading question) has
28 words. `bible_tokens` has 33 rows for this verse. The three extra rows:

| Strong's | Greek (TR) | Should occur | Occurs in DB | DB glosses |
|---|---|---|---|---|
| G1401 (δοῦλος, "servant/bondservant") | δούλοις (v.11, dat. pl.), δούλῳ (v.26, dat. sg.) | 2 | 4 | "unto", "servants", "unto", "servant" |
| G4591 (σημαίνω, "to signify") | ἐσήμανεν (v.19) | 1 | 2 | "he", "signified" |
| G3588 (ὁ, "the" — untranslated article) | ὁ/τοῖς/τοῦ/τῷ (4 occurrences) | 4 | 6 | "." ×6 |

Root cause: when one Greek word required two English words to render (the
dative case rendered "unto ... servants"; the aorist verb rendered
"he ... signified"), the token importer emitted **one row per English
word instead of one row per Greek word**, and stamped both rows with the
same `ancient_text` and `strongs_canonical`. This is not a legitimate
double occurrence of δούλοις in the source — Rev 1:1 uses it exactly
once, addressing "his servants" collectively, distinct from the separate,
singular "his servant John" later in the verse (δούλῳ, also duplicated
the same way).

## Scope of the bug across the whole Bible

Method: for every verse, count occurrences of each root Strong's number in
`bible_tokens` and compare against the Textus Receptus (NT, TR-tagged rows
of STEPBible's TAGNT) or the Masoretic/Leningrad text (OT, STEPBible's
TAHOT, which is the Westminster Leningrad Codex — the standard
machine-readable Masoretic Text). A verse is flagged when the database has
*more* occurrences of a Strong's number than the source text does.

- **HIGH confidence**: two or more of those extra tokens share the exact
  same spelling (`ancient_text`) — an unambiguous exact-duplicate pair,
  the same pattern as Rev 1:1's δούλοις/δούλῳ/ἐσήμανεν.
- **MEDIUM confidence**: the count is still over the source count, but the
  spelling of the "extra" token(s) differs from the others sharing that
  Strong's number — could be a genuine duplication of a different
  inflected form, or a legitimate cross-edition/versification difference.
  Needs a manual look.

Verified: legitimately repeated words (e.g. John's "Verily, verily" /
ἀμὴν ἀμήν, Isaiah 6:3 "Holy, holy, holy") are **not** flagged, since the
source text also contains the word that many times.

**The bug is heavily concentrated in the New Testament:**

| | Verses w/ HIGH finding | Total verses | % affected |
|---|---|---|---|
| New Testament | 3,153 | 7,957 | **39.6%** |
| Old Testament | 689 | 23,145 | 3.0% |

This points to the Greek NT token-import pipeline as the primary source
of the bug — likely because KJV renderings of Greek case/verb forms
routinely need 2+ English words (English is more analytic than Greek),
which is exactly the condition that triggers the duplication.

## Known limitations of this scan

- **Count-based, not position-based.** It catches a Strong's number
  appearing *too often* in a verse; it will not catch a token tagged with
  a plausible-but-wrong Strong's number that doesn't change the per-verse
  tally.
- **1,976 verses had no reference match.** Almost all are legitimate
  KJV-vs-NRSV versification differences (STEPBible's TAGNT/TAHOT use NRSV
  versification; this database uses KJV versification — e.g. many Hebrew
  Psalm superscriptions are verse 1 in the Masoretic Text but unnumbered
  in the KJV). These verses are simply excluded from the scan, not
  silently counted as clean.
- **Some MEDIUM findings reflect reference-data quirks, not DB bugs** —
  e.g. Greek personal-pronoun forms (ἡμῶν, μου) are occasionally tagged
  under a different disambiguated Strong's number in STEPBible's system
  than the plain `G1473` this database uses, which can show up as
  `source_count=0` even when the DB word is fine. When that happens, rely
  on the HIGH-confidence exact-duplicate-text signal (which is
  source-independent) rather than the raw source count.
- Reference data: STEPBible-Data "Translators Amalgamated" GNT/OT
  (CC BY 4.0), https://github.com/STEPBible/STEPBible-Data — TR = Scrivener's
  1894 (the Greek text underlying the KJV); Hebrew OT = Westminster
  Leningrad Codex (the standard Masoretic Text).
