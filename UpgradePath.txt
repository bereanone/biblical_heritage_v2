Upgrade Path
============

This file preserves the postponed feature work and cleanup priorities before the project moves fully into stabilization and review mode.

1. Shared-list/tag import/export
- Fix eLibrary/library cards so they actually import from shared/tag lists.
- Bible cards currently import, but eLibrary cards are still missing.
- eLibrary cards must import even if the local source file is missing.
- If source is missing, preserve the card as readable saved material with navigation disabled or warning.
- Import summary should show Bible cards, eLibrary cards, notes, unsupported/skipped counts.
- UI must never show raw locators such as elibrary-range, OEBPS paths, library_item_research_epubs, compactRef, or offsets.

2. Full vs Compact export modes
- Full export = reference + content.
- Compact export = reference only.
- Exception: note without a reference must export as full note text even in compact mode.
- Bible full: reference + verse text.
- Bible compact: reference only.
- eLibrary full: readable reference/title + selected content/snippet.
- eLibrary compact: readable reference/title only.
- Note with reference full: reference + note.
- Note with reference compact: reference only if meaningful.
- Note without reference compact: full note text.

3. App identity/title
- Restore user-facing title/header so it clearly shows StudyBible 2.0.
- Preferred wording: Biblical Heritage StudyBible 2.0.
- Shorter acceptable wording: StudyBible 2.0 or Biblical Heritage 2.0.
- Do not use Test, Demo, or Legacy.
- Do not change bundle identifier or app container identity without explicit approval.

4. Dirty-tree cleanup campaign
- Stop broad feature work until the dirty tree is cleaned.
- Current tree has many changed files and must be split into reviewed commits.
- No broad 87-file checkpoint.
- Commit small verified changes separately.
- Review startup/recovery cluster separately.
- Review unified EGW/eLibrary cluster separately.
- Quarantine generated/plugin/icon/platform/schema/presentation/test churn until justified.

5. Large-file slimming campaign later
- Do not slim during current stabilization.
- Later candidates:
  - library_book_reader_screen.dart
  - library_catalog_service.dart
  - elibrary_setup_screen.dart
  - elibrary_download_service.dart
  - library_screen_browser.dart
  - startup_coordinator.dart
  - commentary_research_library_service_epub_storage.dart
- Slim one file at a time only after stable commits exist.

6. Backup system
- Backup User Data button should use OS save/share picker.
- User chooses location: iCloud Drive, Files, Google Drive, OneDrive, Dropbox, local folder, USB, etc.
- Backup should include user.db, tags, notes, highlights, markup, bookmarks, presentations, settings, metadata.
- Downloaded EGW EPUB/PDF files are replaceable and should be excluded by default.
- Future optional setting may include downloaded books.
- Add a Restore User Data option to pair with Backup User Data.
- Restore should let the OS/user pick a backup archive through the normal file picker.
- Restore must preview what will be restored before changing anything.
- Restore should warn clearly before replacing current user data.
- Restore should include user.db, tags, notes, highlights, markup, bookmarks, presentations, settings, and metadata.
- Restore should not require restoring downloaded EGW EPUB/PDF files.
- Restore should not delete downloaded books unless the user explicitly chooses a future advanced option.
- Restore should make a safety backup of current user data before replacing it.

7. eLibrary setup wording
- Main setup screen should show simple folder policy:
  - Official EGW EPUBs: ePubs/EGW/
  - Official EGW PDFs: PDFs/EGW/
  - User EPUBs: ePubs/User/
  - User PDFs: PDFs/User/
- Do not emphasize legacy commentary/research folders on normal first-user screen.
- Older folders can be mentioned only in Advanced/Developer diagnostics.

8. Commentary/eLibrary category behavior
- User-facing organization should come from metadata/categories, not physical folder separation.
- All EGW books should be searchable together.
- Filters should include EGW Books, Devotionals, Periodicals, Manuscript Releases, Pamphlets, Misc Collections, EGW Commentaries when items exist.
- Commentary button should use metadata/category and not fragile folder paths.
- Commentary files were zero on the clean download, so commentary content availability still needs review.

9. Offline behavior
- After download/indexing, app should run offline.
- Bible and downloaded eLibrary books should work without Mac/Xcode connection.
- Search should work for already indexed material.
- Downloads/cloud backup require connectivity.

10. App update / eLibrary persistence rule
- App updates must preserve downloaded eLibrary files.
- App updates must preserve the saved Library Root.
- App updates must not force users to re-download EGW files.
- Startup must detect existing ePubs/EGW and PDFs/EGW after an update.
- If the Library Root is inaccessible, show Reselect Library Root instead of resetting silently.
- Never delete or recreate the Library Root during normal app update.

11. Future eLibrary/card display polish
- Saved eLibrary cards should show readable citations such as 3SP 14.2 when available.
- Fallback should be readable title/chapter, never raw internal locator.
- Tapping an imported eLibrary card should navigate if source exists; otherwise preserve readable card.

12. Testing checklist before future commits
- dart analyze.
- App launches.
- Close/reopen from icon.
- Genesis 1 opens.
- Psalm 119 verse numbers are not clipped.
- eLibrary opens.
- Segmented buttons remain readable.
- No white screen.
- No automatic download/index/cleanup/migration at startup.
- No raw eLibrary locator shown in user UI.
- Shared-list import/export round trip works for Bible + eLibrary + notes.
